# เริ่มต้นใช้งาน #

ในส่วนนี้คุณจะพบข้อมูลเกี่ยวกับวิธีเริ่มเขียน instrumentation ด้วย DSL `Whamm`

# การติดตั้ง #

วิธีติดตั้ง `Whamm` ในปัจจุบันคือการโคลนรีโพสิทอรี บิลด์ซอร์สโค้ดด้วยตนเอง แล้วเพิ่มไบนารีที่สร้างได้ลงในตัวแปร `PATH` ของคุณ
ในอนาคต ผู้ใช้จะสามารถดาวน์โหลดไบนารีที่บิลด์ไว้ล่วงหน้าจากหน้า releases บน GH ได้ เนื่องจากเรามีรีลีสของ `Whamm` ที่ติดแท็กและเสถียรแล้ว

ขั้นตอน:
1. โคลน[รีโพ `Whamm`](https://github.com/ejrgilbert/whamm)
2. บิลด์ซอร์สโค้ดด้วย `cargo build --release`
3. เพิ่มไบนารีที่บิลด์ได้ลงใน `PATH` ของคุณ
   ไบนารีนี้ควรอยู่ที่ `target/release/whamm`<sup>[1](#why_target)</sup>

## การทดสอบเบื้องต้น ##
การทดสอบเบื้องต้นที่คุณสามารถรันเพื่อยืนยันว่าไบนารี `Whamm` อยู่ใน path ของคุณและทำงานได้ตามที่คาดหวัง คือการรันคำสั่งต่อไปนี้: `whamm --help`
CLI จะให้ข้อมูลเกี่ยวกับคำสั่งและตัวเลือกต่างๆ ที่พร้อมใช้งาน

# มอนิเตอร์และตัวจัดการ Wasm #

ดังที่กล่าวไว้ใน[บทนำ](../intro.md) `Whamm` ใช้ได้ทั้งเพื่อมอนิเตอร์ **หรือ** ปรับเปลี่ยนการทำงานของโปรแกรม

สิ่งที่เราหมายถึงโดยการ**มอนิเตอร์**การทำงาน คือการ_เก็บข้อมูลบางอย่าง_เกี่ยวกับพฤติกรรมเชิงพลวัตของโปรแกรม
ซึ่งมักใช้ในการดีบัก การบันทึกล็อก และการเก็บเมตริก

สิ่งที่เราหมายถึงโดยการ**ปรับเปลี่ยน**การทำงาน คือการ_เปลี่ยน_พฤติกรรมเชิงพลวัตของโปรแกรมจริงๆ
ลองพิจารณาฟีเจอร์หนึ่งของเครื่องมือดีบักหลายตัว: เมื่อใช้ดีบักเกอร์ นักพัฒนาสามารถตั้งเบรกพอยต์ ตรวจสอบสถานะปัจจุบันของแอปพลิเคชัน และ_เปลี่ยนค่าของตัวแปร_ได้
นี่คือตัวอย่างของการปรับเปลี่ยนพฤติกรรมเชิงพลวัตของแอปพลิเคชันผ่านการเปลี่ยนสถานะ และเป็นสิ่งที่เราจะรองรับใน `Whamm`

อ่านเนื้อหาส่วน "เริ่มต้นใช้งาน" ของหนังสือเล่มนี้ต่อเพื่อดูวิธีเขียน_มอนิเตอร์_และ_ตัวจัดการ_ดังกล่าว

# โครงสร้างของ Instrumentation ใน `Whamm` #

![](../images/anatomy.png)

โครงสร้างหลักของ instrumentation ที่เขียนด้วย `Whamm` ประกอบด้วยสคริปต์ `Whamm` (`instr.mm`) และไลบรารี instrumentation (`instr.wasm`)

ไฟล์ทั้งสองนี้ร่วมกันบอกคอมไพเลอร์ `Whamm` ว่า_จะแทรก_ instrumentation _ที่ไหน_ และ_จะฉีดตรรกะอะไร_ ณ จุดเหล่านั้น

## `instr.mm`  ##
_**ที่ไหน**ที่จะแทรก instrumentation_

สคริปต์ `Whamm` นี้บรรยายหน่วยของ instrumentation โดยระบุจุดที่จะโพรบในแอปพลิเคชันด้วย[ไวยากรณ์โพรบ](./syntax/probes.md)
โพรบเหล่านี้มีตรรกะที่จะฉีด ณ จุดที่แมตช์นั้นอยู่ในเนื้อโพรบ
DSL มีความสามารถเพียงพอต่อการรองรับกรณีการใช้งานมอนิเตอร์บางแบบ อย่างไรก็ตาม เพื่อไม่ให้ขอบเขตของ DSL บานปลาย เราจึงตัดสินใจผลักการเขียนโปรแกรมทั่วไปออกไปยังภาษาใดก็ได้ที่คอมไพล์เป็น Wasm ได้
สคริปต์สามารถเรียกไลบรารี instrumentation ของผู้ใช้ ซึ่งจัดเตรียมไว้เป็น `lib.wasm`

## `lib.wasm` ##
_**ตรรกะอะไร**ที่จะแทรก ณ จุดเป้าหมายของแอปพลิเคชัน_

การจัดหาไลบรารีนี้ให้ `Whamm` เป็นเรื่อง_ทางเลือก_
จำเป็นเฉพาะเมื่อผู้ใช้ต้องการเขียน instrumentation ในภาษาระดับสูงกว่า หรือเมื่อ DSL ไม่มีไวยากรณ์/เครื่องมือบางอย่างที่จำเป็นสำหรับตรรกะ instrumentation
ภาษานี้_ต้องคอมไพล์เป็น Wasm ได้_ เนื่องจากต้องจัดหาไลบรารีให้คอมไพเลอร์ `Whamm` ในรูปไฟล์ Wasm

ผู้ใช้ต้องคำนึงว่าลายเซ็นของฟังก์ชันในไลบรารีที่จะถูกเรียกในเนื้อโพรบ จะต้องมีชนิดที่เข้ากันได้กับ[ชนิดที่ `Whamm` ให้ไว้ในปัจจุบัน](./language.md)
มิฉะนั้น `Whamm` จะคอมไพล์โค้ด instrumentation ของผู้ใช้ไม่ได้

# เครื่องมือที่เป็นประโยชน์ #

นี่คือเครื่องมือบางอย่างที่อาจช่วยได้เมื่อทำงานกับ Wasm:
1. [`wabt`](https://github.com/WebAssembly/wabt) หรือที่รู้จักกันในชื่อ WebAssembly Binary Toolkit
2. [`wasm-tools`](https://github.com/bytecodealliance/wasm-tools)

<a name="why_target">1</a>: เราแนะนำให้เพิ่มไบนารีที่บิลด์ใน `target/` ลงใน path ของคุณ เพราะจะทำให้คุณดึงการเปลี่ยนแปลงล่าสุดบน `master` มาบิลด์เวอร์ชันล่าสุด และมีไบนารีล่าสุดอยู่ใน `PATH` โดยอัตโนมัติ
