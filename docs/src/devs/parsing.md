# เฟสที่ 1: การแยกวิเคราะห์ #

นี่คือเอกสารที่อธิบายวิธี_แยกวิเคราะห์_สคริปต์ `.mm`

## ไวยากรณ์ ##
[whamm.pest]

ไวยากรณ์ของ `Whamm` เขียนด้วยไลบรารี Rust ชื่อ [Pest] ซึ่งเป็นตัวสร้าง parser ที่ใช้ Parsing Expression Grammars (PEG) เป็นอินพุต
การอ่านหนังสือ [Pest] ก่อนจะช่วยให้เข้าใจวิธีอ่านไวยากรณ์ใน [whamm.pest]

Pest แยกวิเคราะห์สคริปต์ `.mm` ที่ส่งเข้ามาและสร้างชุด `Rule` ที่แมตช์ ซึ่งจากนั้นถูกท่องไปใน [`whamm_parser.rs`] เพื่อสร้าง Abstract Syntax Tree (AST) ของ `Whamm`
`Rule` เหล่านี้สอดคล้องกับชื่อที่ใช้ในไวยากรณ์ `whamm.pest`

ตรรกะในการสร้าง AST จาก Pest `Rule` ติดตามได้โดยเริ่มจากจุดเข้าของการแยกวิเคราะห์: ฟังก์ชัน `parse_script` ที่พบในไฟล์ [`whamm_parser.rs`]

[whamm.pest]: https://github.com/ejrgilbert/whamm/blob/master/src/parser/whamm.pest
[Pest]: https://pest.rs/book/

[`whamm_parser.rs`]: https://github.com/ejrgilbert/whamm/blob/master/src/parser/whamm_parser.rs

## Abstract Syntax Tree (AST) ##

เราใช้ AST แทนสคริปต์ `.mm` หลังการแยกวิเคราะห์
AST นี้ถูกนำไปใช้ต่างกันในแต่ละเฟสของคอมไพเลอร์ที่ตามมา

ระหว่าง [**การตรวจสอบ**](verifying.md) AST ถูกใช้สร้าง `SymbolTable` และทำการตรวจชนิด

ขณะ [**แปลง AST**](transform_ast.md) ให้เป็นตัวแทนของกลยุทธ์การอินเจกต์ AST จะถูกเยี่ยมชมและจัดโครงสร้างใหม่ให้คอมไพล์ได้ง่ายขึ้นสำหรับแต่ละกลยุทธ์
แต่ละโหนดมีข้อมูลใหม่ที่จำเพาะต่อกลยุทธ์ ซึ่งมีประโยชน์ระหว่างการปล่อยโค้ด

ขณะ [**ปล่อยโค้ด**](emit/emitting.md) จะใช้_รูปแบบ AST ที่เรียบง่ายกว่า_ที่กล่าวถึงข้างต้น เพื่อค้นหาคำสั่งโกลบอลและวนซ้ำนิยามของโพรบเพื่อฉีดมันเข้าไปในตำแหน่งที่สนใจในโปรแกรม Wasm
